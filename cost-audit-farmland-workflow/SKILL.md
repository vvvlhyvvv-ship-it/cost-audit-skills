# 高标准农田造价审核工作流（主编排）

> 固化某县 2025 高标准农田项目全过程的审核方法论，把"用户亲授的三步法 + 合同变更汇总表枢纽 + 批复概算控制层 + 风险清单/核减建议/情况说明"串成一条可复用的端到端流程。
> 子技能：
> - `visa-pdf-caliber-summary` —— 扫描件签证/预算表 → 指定口径（如 19 项）汇总（第③步"签证量"输入）
> - `cost-audit-doc-writer` —— 情况说明 / 审核报告 / 进度复核公文撰写（交付物④）
> - `settlement-merge-summary` —— 结算书明细（Sheet2）→ 合并汇总表更新；**审定合计与明细不符**时的公式链溯源、缺陷定位与核查报告生成
>
> 本技能不做 OCR 细节，只负责**编排、定位、风险判定、交付物衔接**；具体解析与写作交给子技能。

---

## ⛔ 强制规则（MUST）

1. **三类资料定位不可混**：
   - **认可工作量 = 合同 + 签证 + 变更** —— 均"经建设单位认可"，即认可的设计范围工作量。
   - **结算报送** —— 施工单位报送的结算量（claim）。
   - **复核报告** —— 实际量（现场实测/复核，单位亦经建设单位认可）。
2. **风险是双轴**：
   - **超量风险** = 认可工作量 被 报送结算 超出（差异列 = 签证+变更 − 结算报送，负值即超报）。
   - **超概风险** = 各口径量 超出 **批复概算（总体控制）**。
3. **合同变更汇总表是总装枢纽** —— 所有数据源（一标~四标签证、设计变更、原合同、结算报送、复核报告）最后都汇入它的列，风险点在此落位。
4. **工程量超概 ≠ 金额超概**：金额 = 工程量 × 合同单价。合同单价低于概算时，工程量超概可被单价差抵消（如客土土方量：方量超 8.5% 但金额未超）。**判定超概必须同时看"量"和"价"两个维度**。
5. **公文严格按模板直设格式**（见 `cost-audit-doc-writer`，python-docx 直设，禁用样式名）。

## 一、三类资料与风险逻辑（核心心智模型）

```
           认可工作量（建设单位确认）
  ┌─────────────────────────────────────────┐
  合同  +  签证(四方确认净增减)  +  设计变更
  └─────────────────────────────────────────┘
        │                    │
        │ 对比①              │ 对比②
        ▼                    ▼
   结算报送(claim)      复核报告(实际量)
        │                    │
        ▼                    ▼
   超量风险：认可量 < 报送   实际 vs 报送（水分）
        │
        ▼
   对比③：认可量 vs 复核报告（实际）
```

- **超量**：凡"超出经建设单位认可确定资料的工作量"即存在超量风险。
- **超概**：任何口径量（设计变更合计 / 签证+变更 / 结算报送）超出**批复概算计划量**即超概。

## 二、标准三步流程（每步 WHY）

| 步骤 | 用户派活 | 为什么（WHY） | 产出 |
|---|---|---|---|
| ① 政策合规 | "整理相关政策/规范" | 签证、变更、结算程序必须先合规，否则量算对也站不住（财建〔2004〕369号、财建〔2009〕648号、国务院令712号支撑） | 政策合规性梳理 |
| ② 结算 vs 复核 + 现场 | "结算与复核量对比分析" | 看施工单位报的量 vs 现场实际量，暴露水分 | 结算/复核对比 + 现场情况 |
| ③ 合同 + 签证汇总对比 | "四个标段签证工程量按口径汇总" | 把合同+签证+变更拼成认可工作量，对接枢纽表，看认可量是否超 | 四方签证汇总（净增减） |

> 用户原话脉络："通过合同额+签证+变更的工程量与报送结算对比，再通过复核报告与报送结算对比……多次对比就能发现风险点。超出经建设单位认可确定资料的工作量就会存在超量风险。"

## 三、文件枢纽：合同变更汇总表.xlsx

**列结构**（某县 2025 实例，19 项口径）：

```
序号 / 单项名称 / 单位
  → 一标 / 二标段 / 三标 / 四标   ← 四方签证净增减（调入−调出），即 visa-pdf-caliber-summary 的输出直接喂入
  → 四方签证合计                  ← 四标求和
  → 设计变更合计                  ← 设计变更量
  → 签证+变更                    ← 四方签证合计 + 设计变更合计 = 认可调整量
  → 原合同                       ← 合同基线
  → 结算报送                     ← 施工单位报送
  → 复核报告                     ← 实际量
  → 差异列                       ← = 签证+变更 − 结算报送（负值=报送超认可量→超报风险）
```

- **关键验证**：`设计变更合计`列 ≈ **批复概算正文的建设规模计划量**（逐项吻合，如底土平整土方量 28735.23≈28735、机械翻耕 20000=20000、混凝土路 23505=23505、硫酸亚铁 572.29=572.29、进地盖板 34=34……）。据此判定：**设计变更合计 = 经批准的概算规模（控制上限）**。
- 该表是"认可工作量 vs 报送结算 vs 复核报告"三轴对比的总装表，风险点在此落位。

## 四、概算控制层（批复概算对比）

批复文件（如吕农发〔2025〕68号）特征：**调整前后总投资不变（总体控制），仅建设内容/任务量调整**。它是所有数据的**概算控制上限**。

**对比框架（已交叉验证成立）**：

| 轴 | 含义 | 来源 |
|---|---|---|
| 批复计划量 | 概算控制量 | 批复正文建设内容规模 |
| 设计变更合计 | 经批准的概算规模 | 合同变更汇总表该列（≈批复计划量） |
| 四方签证合计 | 批复计划之外的额外调整 | visa-pdf-caliber-summary 输出 |
| 签证+变更 | 最终认可工作量 | 设计变更合计 + 四方签证合计 |

**超概判定公式**：
```
某口径超概量  = 该口径量 − 批复计划量
超概比例(%)   = 超概量 / 批复计划量 × 100
```
- 签证+变更 vs 批复 → 认可量是否超概
- 结算报送 vs 批复 → 报送是否超概
- 原合同 vs 批复 → 合同是否漏列/多列（原合同=0 即漏列）

**金额维度（关键，勿漏）**：
```
分部金额超概 = Σ(该分部各单项 (报送量−概算量) × 合同单价)   # 或认可量口径
```
- 工程量超概 **不一定** 金额超概：客土土方量方量超 +8.53% 但合同单价低于概算 → 金额未超。
- 分部金额超概主因常为**合同单价高于概算**（如土壤改良项）或**新增子目**（如田间道路过路管涵/漫水路/混凝土挡土墙）。

**待厘清口径（实操中必问用户）**：
1. 面积类三项（底土平整亩/客土回填面积亩/表土剥离面积亩）汇总表只有净增减、批复给总规模，口径不同不能直接比。
2. 原合同=0 是漏列还是列在别处？
3. 认可量>批复但报送<批复的矛盾（如路边沟）→ 是否签证+变更混入了非该子目？
4. 实质超概（如客土土方量结算超 8.5%）如何处理（核减/专项说明/设计再调整）？

## 五、交付物清单

1. **四方签证工程量汇总**（净增减＝调入−调出）—— 由 `visa-pdf-caliber-summary` 产出，喂入枢纽表一标~四标列。
2. **合同变更汇总表.xlsx** —— 枢纽，汇总所有口径。
3. **超量/超概风险点清单** —— 按严重度（🔴/🟠/🟡/🟢）列出超量、超概项及原因。
4. **核减建议 / 审核建议（公文）** —— 由 `cost-audit-doc-writer` 产出（如《初步审核情况说明》"四、审核建议"章节）。

## 六、审核建议撰写范式（某县实例，可套用）

结构（4~5 条，语言按公文组织，数字严格照用户给）：
1. **整体结论**：整体结算金额未超出概算控制范围；但部分分部超出（点名金额，如土壤改良 +93.33 万、田间道路 +78.57 万）。
2. **原因①（单价）**：某分部超概主因为合同单价高于概算单价。
3. **原因②（量/新增子目）**：某分部超概主因为复核工程量超概算 + 新增子目（点名如过路管涵、漫水路、混凝土挡土墙）。
4. **例外说明（量超价不超）**：某项工程量虽超概算方量，但合同单价低于概算，整体金额未超。

> 实例印证：用户确认的"过路管涵/漫水路/混凝土挡土墙"正是签证汇总 unmapped 清单中被判定"不在 19 项签证口径、属结算新增子目"而排除的道路子目——审核建议中将其确认为田间道路超概原因，前后逻辑自洽。

## 七、子技能调用指引

- **扫描件签证 → 口径汇总**：调用 `visa-pdf-caliber-summary`。关注其 6 条强制规则（预算页单侧列、净增减口径、quota 错位双保险、按名称列锚定行、父行跳过、人工补录）。
- **审核公文撰写**：调用 `cost-audit-doc-writer`。关注逐 run 直设字体（标题黑体18/一级楷体16/正文仿宋16，首行缩进32pt，两端对齐）、主体具名、真实单位落款、边距套系确认。
- **结算书明细 → 合并汇总**：调用 `settlement-merge-summary`。该技能固化了两条**易错铁律**：
  ① 匹配主键必须是 **(父类别名, 定额名, 单位, 单价) 四元组**（只用后三项会把同定额跨父类别合并、金额翻倍）；
  ② **金额搬源表原值、工程量保留源表完整精度**（工程量 round 到 3 位会 ×单价放大成几十元级偏差）。
  落盘后必须做四项校验（Σ行=合计=r103、无未消费聚合项、匹配率、**逐行 `工程量×单价==金额`**）。
  当委托方或自己发现"审定的合计对不上"时，直接跑 `gap_report.py` 一条命令出核查报告。
- **OCR/渲染/解析细节**：一律交给 `visa-pdf-caliber-summary`，本技能不重复实现。

## 八、标准工作流（端到端）

1. **接收项目** → 确认三类资料是否齐全（合同 / 签证PDF / 设计变更 / 结算报送 / 复核报告 / 批复概算）。
2. **① 政策合规**：梳理适用的造价结算、政府投资财政评审、高标准农田专项、程序合规法规（见 learning-case 文档第四章）。
3. **③ 签证汇总**：调用 `visa-pdf-caliber-summary` 把四方签证按口径汇总为净增减 → 喂入枢纽表一标~四标。
4. **组装枢纽表**：把设计变更、原合同、结算报送、复核报告汇入合同变更汇总表，算差异列。
   - 结算报送/复核数据的**明细口径核对**若涉及"结算书 Sheet2 → 合并汇总表"，调用 `settlement-merge-summary`；
     该表内的合计与明细一旦不符，先按该技能的公式链溯源定位缺陷，再谈风险判定。
5. **④ 概算控制对比**：读批复概算，验证"设计变更合计≈批复计划量"，逐单项算超概量/比例，区分量/价维度。
6. **② 结算 vs 复核 + 现场**：对比实际量 vs 报送量，标注水分。
7. **生成风险清单**：按严重度列超量/超概项及原因，厘清待问口径。
8. **撰写审核建议/核减建议**：调用 `cost-audit-doc-writer` 产出公文。
9. **交叉核对 + 交付**：已知值对账、unmapped 排查、视觉抽核（继承 visa 技能的复核方法论）；`present_files` 交付。

## 九、典型踩坑（跨技能交叉引用）

- **预算页漏识**（visa 坑A）：仅调入/调出续页被跳过 → 整村缺失。解决：单侧列即识别 + 全量扫描兜底。
- **quota 错位漏计体积行**（visa 坑B）：定额号挂到表头行，土方量漏计 → 双保险补录（父项上下文+名称关键词）。
- **行串行/漏行**（visa 坑C）：密集页按数值 y 聚类错位 → 按单项名称列锚定行。
- **合并漏层级**（结算送审稿阶段）：多村合并时只留一级+末级，丢二级细分标题 → 栈追踪父路径提取全部层级。
- **合并键误用序号**（结算送审稿阶段）：跨村同名未并/同号误并 → 改用语义稳定字段（名称+单位+父路径）。
- **概算层漏看金额维度**：只比工程量认为超概，忽略合同低价抵消 → 量价双维度判定。
- **公文格式漂移**（doc-writer 坑）：依赖 Word 样式名克隆失败 → python-docx 逐 run 直设。
