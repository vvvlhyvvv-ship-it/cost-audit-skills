# 公文 / 长文档版式标准与套版

> 沉淀自 2026-09-11 某县两份实施方案送审稿的套版作业（母本套版 → 通用公文格式改造 → 行距1.5倍+标题防落单）。
> 使用者：造价工程师，Word/WPS 环境，Windows 11。

---

## ⛔ 强制执行规则（MUST）

1. **一律现读母本实测，不凭记忆**。记忆里的格式数字（本文件中的数字也一样）**全部按"待核"处理**——同类文件母本实测边距曾与记录不符（见 §五 坑 1）。
2. **逐 run 直接格式化**（直设 `w:rFonts` 的 `eastAsia/ascii/hAnsi`），**严禁依赖样式名**。用户的编辑器对样式克隆不稳定，直设字体最稳。
3. **中文字体必须设 `w:eastAsia`**，只设 `font.name` 对中文无效。
4. **改版式后必须重跑目录域**（页码会变），否则目录页码是错的。
5. **各级标题必须设 `w:keepNext`**（长文档），否则标题会孤立在页尾、正文翻页。
6. **改页边距后必须复核表格宽度**，原表列宽常按旧版心满宽设定，会溢出。
7. **落地前先备份**到 `.workbuddy/backup/`，带时间戳。
8. **两套母本不可混用**（见 §一），动笔前先确认用哪套。

## 一、两套版式基准（先确认用哪套！）

### A. 通用公文母本（跨项目默认）

- **母本**：`<项目工作区>\某国家现代农业产业园蛋鸡产村融合发展示范项目\审核过程文件\某国家现代农业产业园蛋鸡产村融合发展示范项目初步审核情况说明.docx`
- **地位**：用户 2026-08-07 指定「今后所有同类写作都以该模板为标准」。

| 元素 | 规格 |
|---|---|
| 页面 | A4 21×29.7cm；**页边距 上下 2.54 / 左右 3.17cm；页眉 1.50 / 页脚 1.75cm** |
| 标题 | **黑体 18pt**、居中 |
| 称谓 / 正文 / 落款 | **仿宋 16pt**、两端对齐；正文首行缩进 **32pt**（2 字） |
| 一级标题（一、二、三…） | **楷体 16pt**、首行缩进 32pt |
| 行距 | 母本未设（单倍）；**长文档套用时用 1.5 倍**（用户 2026-09-11 指定） |
| 母本结构 | 只有「标题 / 一级标题 / 正文 / 落款」四级，**无二三级标题、无表格、无目录** |
| 机制 | 全篇**直接格式化**（run/paragraph 直设字体，非样式名） |

> 二三级标题母本未定义，**长文档套用时按用户 2026-09-11 选定**：一级黑体16 / 二级楷体16 / 三级仿宋16加粗。

### B. 某县项目专用母本（仅限该项目两份实施方案送审稿）

- **母本**：`某县餐厨垃圾处理专项实施方案 (1).docx`（某会计师事务所 2026.9，项目工作区根目录）
- **与 A 的区别**：**边距不同、一级标题字体不同**，混用即错。

| 元素 | 规格 |
|---|---|
| 页面 | A4；页边距 上下 **25.4mm** / 左右 **28.8mm**；页眉页脚 12.7mm |
| 封面主标题 | 方正小标宋简体 **24pt** 居中（行距 1.2 倍） |
| 封面副题 | 方正小标宋简体 16pt 居中 |
| 一级标题（一、二、三…） | **黑体 16pt**、首行缩进 32pt、固定行距 28pt、段前 19 / 段后 7pt |
| 二级标题（（一）（二）…） | 楷体 16pt、首行缩进 32pt |
| 三级条目（1. 2. 3.） | 仿宋 16pt **加粗**、首行缩进 32pt |
| 正文 | 仿宋 16pt、首行缩进 32pt、固定行距 **28pt** |
| 表题 / 表格 | 表题 仿宋 14pt 居中；表格 宋体 11pt、表头加粗居中 |

> 该母本自身有 5 处不统一（一级标题加粗不一致、缺"七、"、个别缩进 16pt、封面标题重复、两张表风格不一），套版前须与用户确认基准。

## 二、长文档套用规范（在 A 或 B 之上叠加）

| 项 | 规则 |
|---|---|
| **行距** | **1.5 倍**（`w:spacing line=360 lineRule=auto`）。母本单倍，但用户 2026-09-11 明确长文档用 1.5 倍 |
| **标题防落单** | 各级标题（一级/二级/三级/表题）设 **`w:keepNext`** "与下段同页"。⚠️ **目录条目不加 `keepNext`**——否则整片目录会被拖到下一页 |
| **目录** | 三级目录（1~3 级），**必须用 Word 更新域生成真实页码**，不是占位；域指令用 `TOC \o "1-2" \z \u`（**去掉 `\h`**，否则条目带蓝色下划线超链接） |
| **目录条目字体** | 单独定，**不可套标题字体**（否则目录整片黑）：TOC1 黑体14加粗 / TOC2 楷体14 / TOC3 仿宋14 |
| **目录独立起页** | 报告类文档见下 §二·补充「报告类文档体例」——**目录打头 + 分节符**，非封面页在前 |
| **表格** | 列宽按新版心宽度**等比缩放**并锁定 `w:tblLayout=fixed` |
| **大纲级别** | 重建 `w:outlineLvl`：一级→0、二级→1、三级→2（否则目录抓不到） |

### 补充：报告类文档体例（用户 2026-09-21 定版）

> 沉淀自某智慧停车项目《投资风险评估报告》成稿时用户的格式调整（逐项实测确认）。
> **今后同类咨询/评估报告按此执行。**

**一、结构体例**

| 项 | 定版规则 |
|---|---|
| 封面 | **不设独立封面页**。主标题（黑体 18pt 居中，可 2 行）直接作为正文文头 |
| 文档顺序 | **目录 → 主标题 → 称谓 → 正文**（目录打头） |
| 目录与正文分界 | 用 **分节符（下一页）**，**不用分页符**；全文共 2 节 |
| 页码 | 正文所在节设 `w:pgNumType w:start="1"`，**正文页码从 1 重新编号**；目录所在节页脚留空、不显示页码 |
| 主标题后 | 紧接称谓与正文，**不另起页** |

**二、目录版式**

| 元素 | 定版规则 |
|---|---|
| 「目　　录」标题 | 中间为**全角空格**；黑体 **18pt**、居中、**固定行距 28pt**、段前 6pt、段后 12pt、`keepNext` |
| 标题留白 | 「目录」标题**上下各留 1 个空段落**（同格式：居中 / 固定 28pt / 段前 6 / 段后 12 / keepNext） |
| 一级条目 | 黑体 14pt、左缩进 0 |
| 二级条目 | 楷体 14pt、左缩进 0.74cm |
| **条目行距** | **1.5 倍**（与正文一致）→ 27 条会跨 2 页，**用户接受跨页** |
| ⚠️ 样式同步 | 行距/字体必须**同时写进 `toc 1` / `toc 2` 样式**。只改段落 → 更新域重建条目时**回弹**（实测目录 2 页→1 页、总页 20→19） |

**三、落款版式**

- 正文末段 → **一个空段落** → 单位名（右对齐、段前 6pt）→ 日期（段前 6pt）
- 用户版日期行取「两端对齐 + 首行缩进 240pt」（**手工对位，非规范值**）——套版时建议与用户确认，不要默认照抄

**四、中文标点规范（硬要求，起草时即应遵守）**

| 项 | 要求 | 本次用户逐处修订量 |
|---|---|---|
| 序号 | 用**顿号**「1、2、3、」——**禁用**半角点「1. 2. 3.」 | 45 处 |
| 引号 | 用**中文全角弯引号**「“ ”」——**禁用**半角直引号「"」 | 3 处 |

> 这两条是中文公文/正式报告的基本规范，**不要等用户改**。

## 三、长文档套版执行链（五步，每步幂等可重跑）

1. **只读探测**：读目标文档的封面 / 目录域范围 / 分节 / 标题层级现状。
   - **必须先确认层级形态**：同一项目两份文档的第三级可能一种是 `（一）`、一种是 `X.Y.Z`，正则要分别覆盖。
2. **备份** → `.workbuddy/backup/<原名>.<用途>.<时间戳>.bak.docx`。
3. **套版**：逐段直设字体 + 边距 + 行距 + 首行缩进；重建 `w:outlineLvl`；标题设 `w:keepNext`。
   - 脚本：`scripts/format_docx.py`
4. **表格列宽适配**（同脚本内 `fit_tables()`）。
5. **更新目录域 + 页码**：Word COM `TablesOfContents(i).Update()` → `Fields.Update()` → `Repaginate()` → `Save()`；导出 PDF 目视。
   - 脚本：`scripts/update_toc_fields.py`

**核验**：`scripts/verify_format.py`（行距分布 / keepNext 计数 + 全册落单标题扫描）。

### 补充：只改内容、不动版式的做法（2026-09-21 某智慧停车报告实测）

场景：**文档版式已定稿并通过用户确认，只需重写正文**（如报告由"复核式"改版为"独立风险评估式"）。

🔴 **不要重建母本**——那会把分节、页码重编、页脚域、TOC 样式全部重做一遍，风险高。
**正解：以已定稿 docx 为母本，按段落类型克隆格式、只换文字。**

1. 先 `probe_docx_format.py` 定位各类段落的**样板索引**：
   主标题 / 称谓 / 正文 / 一级标题 / 二级标题 / 空段 / 落款单位名 / 落款日期
2. 逐段克隆：
   ```python
   el = copy.deepcopy(exemplar._element)
   for ch in list(el):                     # 只留 pPr
       if ch.tag != qn('w:pPr'): el.remove(ch)
   r = copy.deepcopy(r_exemplar)           # run 的 rPr 也深拷贝
   for ch in list(r):
       if ch.tag != qn('w:rPr'): r.remove(ch)
   t = OxmlElement('w:t'); t.set(qn('xml:space'), 'preserve'); t.text = text
   r.append(t); el.append(r)
   ```
3. 删除原正文段，**但必须保留承载分节符的那一段**（其 `pPr/sectPr` 定义节属性）；
   新段一律 `body.find(qn('w:sectPr')).addprevious(el)` 插到 **body 级 sectPr 之前**
4. Word COM 更新目录域 → 导出 PDF

→ 分节、`pgNumType start=1`、页脚普通段落域、`toc 1`/`toc 2`/`Hyperlink` 样式
**全部自动继承，零改版风险**。

⚠️ 页数换算参考（A4 / 边距 上下2.54·左右3.175 / 正文 16pt / 行距 1.5 倍）：
**约 350 字/页**（实测 12,918 字正文 → 27 页，含标题段与分段空行）。

## 四、硬坑清单（全部踩过，务必规避）

1. **记忆里的边距数字不可信**。本技能曾记"情况说明边距 上下1.0 / 左右1.25cm"，2026-09-11 实测母本 + 工程内 **6 份**同类文件，**边距完全一致为 2.54/3.17cm**，1.25/1.0 在现有文件中查无实例 → 已作废。**任何格式数字都要现读母本。**
2. **`<w:keepNext/>` 不带属性即默认生效**。用 python-docx 核验时若写 `el.get(qn('w:val'))`，对"存在但无 val"的情况返回 `None`，**会被误判成"未设置"**。判定存在性要看**元素本身**（`ppr.find(qn('w:keepNext')) is not None`），或直接 dump `pPr` 子元素名。
3. **Word 更新目录域会重新生成 TOC 条目为新段落**，其行距/字体回到 TOC 样式 → **TOC 样式本身也必须设好**行距与字体，不能只改段落。
4. **Word COM 逐段取 `.Information(3)`（页码）会触发反复重排**，几百段即卡到超时。定位某标题页码请用 `Content.Find`（可 `Forward=False` 反向搜索以跳过前置目录条目），**只在目标段上取页码**。
5. **Word COM 被中断后要双清**：①`WINWORD.EXE` 进程 ②孤立的 `~$*.docx` 属主文件。**仅杀进程不够**——孤立属主文件仍会让 Word 提示"文件正在使用中，只能只读打开"。判断进程可否安全结束：`tasklist /V` 看窗口标题，`HardwareMonitorWindow` = 后台隐藏实例。
6. **Word 会重写 XML**。python-docx 写完 → Word 一开一存，元素顺序/属性可能被规范化，所以**核验要看 Word 落盘后的文件**，且优先**导出 PDF 目视**（比读 XML 可靠）。
7. **表格列宽在改边距后必查**。例：原列宽合计 15.24cm = 旧版心（21−2.88×2），新边距 3.17 后版心仅 14.66cm → 48 张表**全部溢出 0.58cm**。
8. **空段落可能带大纲级别**（历史遗留，套版时必查）。实例：某送审稿索引 206 的空段落带 `outlineLvl=0`，压在"第一章"之前——虽当次未生成空目录行（目录条目数 = 12+50+141 精确吻合），但属隐患（部分 Word 版本会显示空行）。**套版脚本须对空段落调用 `clear_outline()` 清掉大纲级别。**
9. **不要在生产文档里"顺手"改内容**。套版只动格式；发现内容问题单独报告用户。
10. 🔴 **"以冒号结尾 + 短句"判定称谓会误伤正文引导句**（2026-09-21 某智慧停车项目实测踩坑）。
    - 反例：`为便于建设单位逐项落实，本次评估汇总需补充完善的事项如下：`（28字）被误判为公文主送机关 → **漏设首行缩进**，被用户当场指出。
    - 中文公文中 `……如下：` `……包括：` `……主要有：` 这类**正文引导句极多**，形态与称谓相似。
    - **正确判据须三重**：①以「：」结尾且 <30 字 ②**不含逗号/句号**（引导句必有标点）③**仅限文首**（`stats["body"]==0`）。
    - 通用原则：**用条件式控制排版时，先写"否定条件"排除同类干扰项**。宁可漏判（人工补），不可误伤。
    - **核验方法**：写分组统计脚本——按 主标题/一级/二级/正文/称谓/落款 六类，分别统计有/无缩进数并**列出所有无缩进段落文本**；注意主标题行会误归入"正文"类，须按位置排除。
11. 🔴 **Word 目录的四连坑**（2026-09-21 某智慧停车项目报告实测踩坑，一次全踩）。
    - **坑 A｜样式名是小写 `toc 1` / `toc 2`，不是 `TOC 1`**。用 python-docx 建大写 `TOC 1` 样式**不会被 Word 采用**，Word 落盘后实际套用的是内置小写样式。诊断法：读目录条目 `p.style.name`，若显示 `TOC 1 (样式不存在)` 即说明建错了名。**正解**：既建/改小写样式，也同时直设段落格式（双保险）。
    - **坑 B｜蓝色下划线来自 `Hyperlink` 字符样式，不是 TOC 样式**。Word 生成目录条目时会套 `Hyperlink` 字符样式（默认色 `0026E5` + 单下划线）。**只改 TOC 段落样式无效**，必须同时把 `Hyperlink` 字符样式改为目标字体/黑色/`w:u val="none"`。注意 `Hyperlink` 是 **CHARACTER 型**样式，**没有 `.paragraph_format`**，只能设 font 与 `rPr`。
    - **坑 C｜样式重名会自动加序号**。若目标样式已存在又 `add_style` 同名，python-docx 会静默生成 `TOC 11`/`TOC 21` 之类副本，反而污染文档。清理法：`st.element.getparent().remove(st.element)`。
    - **坑 D｜只改样式仍压不住行距，必须写段落级 `w:spacing`**。目录条目可能带直接格式，覆盖样式。**可靠做法**：逐条直接写 `w:spacing`，行距用**固定值**（`lineRule="exact"`）——一级条目 19pt、二级 18pt，段前后 0；再清掉 run 上残留的 `w:color`/`w:u`/`w:shd` 并重设字体。这样 27 条目录可从 2 页压到 1 页（实测总页 21→20）。
    - **判定目录是否单页**：看 Word COM `ComputeStatistics(2)` 总页数变化 + 目录首条页码是否前移；再渲染目录页 PNG 目视确认无第二页残留。
12. 🔴 **页码放进「浮动文本框」会导致页码不逐页刷新**（2026-09-21 某智慧停车报告实测）。
    - **现象**：用户调整版的页脚页码被置于 `<wps:txbx>` 浮动文本框内（`wp:anchor` + `mc:AlternateContent`，`extent` 5.08×5.08cm，`relativeFrom="margin"` 水平居中），导出 PDF 后**正文第 10 页起页码全部显示「1」**（第 1~9 页正常）。逐字符提取确认该处只有一个字符 `1`，非「10」被截断。
    - **已排除**：**不是域缓存问题**——用 `Fields.Update()` + `TablesOfContents.Update()` 强制更新后重新导出，现象不变。
    - **附带**：文本框内页码字体为 Calibri 9pt（我原设的普通段落页码为仿宋 12pt）。
    - **处置建议**：页码应放在**页脚的普通段落**里（`footer.paragraphs[0]` 内插 `PAGE` 域），**不要用浮动文本框**。

## 五、核验方法（推荐顺序）

1. **脚本核验**：行距分布是否单一取值、keepNext 计数是否等于标题数、`outlineLvl` 分布、表格超版心张数是否 0。
2. **导出 PDF → 转 PNG 目视**（pymupdf，dpi≈110）：抽查封面、目录首页、正文首页、表格页。
3. **落单标题离线全册扫描**：逐页取文本，判断**每页最后一个非空行**是否匹配标题正则。
   - ⚠️ 排除误报：目录条目（含省略号 + 页码行）、表格内数字行（如 `42.5 万 t` 会被 `\d+\.\d+` 误命中）。
4. **定位验证**：对用户点名的具体标题，报告「标题页码 / 纵向距页顶 / 上一段页码 / 下一段页码」，用页码关系自证是否已防落单。纵向距页顶 ≈ 上边距（如 72pt = 2.54cm）即说明它是该页第一行。
5. **页码逐页核查（必做，不能只看首页）**：用 pymupdf 取**每页底部 60pt 区域**的 span（含字体名与字号），确认页码**单调递增、与页序一致、且分节起始值正确**。
   - 取法：`page.get_text("dict", clip=fitz.Rect(0, h-60, w, h))["blocks"]` → 逐 span 取 `text` / `font` / `size`。
   - **实例价值**：2026-09-21 某智慧停车报告即由此发现「正文第 10 页起页码全部为 1」的缺陷——若只核首页（显示 1）会**完全漏掉**。
   - 同时核对页码**字体**是否为 Word 默认的 Calibri（西文字体），而非既定的中文字体（本案例应为仿宋）。
