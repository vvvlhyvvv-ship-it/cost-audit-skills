# 投资风险评估报告编制工作流（五席核验法）

> 沉淀自 2026-09-21 某县城市智慧停车一张网建设项目（一期）投资风险评估。
> 使用者：造价工程师 / 会计师事务所，Word 环境，Windows。

---

## 一、何时用本技能

用户要求**对一份可研报告做独立复核评估**并出报告时。典型场景：
- 受建设单位委托，出具第三方咨询意见，**协助项目通过立项审批**
- 政府投资项目 / 国有企业投资项目（尤其信息化、智慧城市、基础设施类）
- 需要同时覆盖**财会、造价、需求、合规**多专业视角

**不适用**：单纯的工程造价结算审核（见 `settlement-merge-summary`）、
单纯的公文撰写（见 `cost-audit-doc-writer`）。

### 5.3 等额本金还本付息
```
年还本 = P/n（固定）
第 k 年利息 = (P - P/n×(k-1)) × r
n 年总利息 = P × r × (n+1) / 2
年均利息   = P × r × (n+1) / (2n)
```

### 5.4 🔴 盈亏平衡法（识别"成本漏项"的利器）
**当可研某项成本"只写口径不给金额"时，不要直接指控漏算**，
而是**反算该成本的上限**——让项目不亏损的临界值：

```
令 利润总额 = 0：
  可容纳的最大成本 = 不含税收入 − 其他全部固定成本
  临界单价 = 最大成本 ÷ 业务量
```

**实例（充电桩购电成本）**：
- 前提：充电服务费 0.40 元/kWh，年充电量 1,152,000 kWh，收入 46.08 万元（占 87.07%）
- 解法：令利润总额=0，反算出**临界购电价 0.15 元/kWh**
- 论据力量：**一般工商业到户电价约 0.55~0.85 元/kWh** → 差距自明，**无需我方定性**
- 优点：**客观中立、不指控编制单位、把判断权交给审批部门**

**稳健性必做**：换用不同折旧摊销口径、是否可抵进项、是否缴增值税，
分别求解，给出区间与"最宽松假设下的上限"。
实例中即便不计折旧摊销，临界值也仅 0.26 元/kWh——**结论不受口径影响**。

**双路径互证**：再用"反推可研隐含成本"独立验证一次。
实例：可研利润 11.99 万反推隐含电费 11.85 万元（折 0.1029 元/kWh），
与临界值路径（0.1499~0.1560）同量级 → **两套独立方法互证，可信度大幅提升**。

### 5.5 多口径反算（当某个指标"不可复现"时）
不要轻易下"算错"结论。先把**所有可能的口径都试一遍**：

| 口径 | 公式 |
|---|---|
| 净利润 ÷ 项目总投资 | 标准 ROI 近似 |
| 净利润 ÷ 建设投资 | — |
| 利润总额 ÷ 项目总投资 | — |
| **利润总额 ÷ 建设投资** | ← 实例中此项与披露值吻合到 0.0026 pt |
| 息税前利润 ÷ 项目总投资 | 标准 ROI |

**实例收获**：原判"投资收益率 5.86% 无法复现"，
经多口径反算后发现 **11.99 ÷ 204.70 = 5.8574%** 可吻合，
故修正为"**数值可复现，但口径非标准指标**"——降级为 🟡。

## 六、常见可研缺陷清单（照此逐项打勾）

### 6.1 财务侧
- [ ] 进项税计提基数与投资估算表对不上（反推基数 ÷ 税率 ≠ 资产原值）
- [ ] 年折旧额 × 折旧年限 ≠ 设备原值
- [ ] 年摊销额 × 摊销年限 ≠ 软件原值
- [ ] 成本表某项"按实际需要估算"但无金额 ← **最高频、最致命**
- [ ] 建设期利息只能由"均额法"得出但未说明方法
- [ ] 未附完整现金流量表、还本付息计划表
- [ ] 偿债备付率/利息备付率复算不符 —— ⚠️ **注意查"平均值"是否为末年值**
- [ ] 基准收益率取值偏低（基础性6% / 经营性基础设施8% / 一般经营性12%）

### 6.2 造价侧
- [ ] 多个模块单价完全相同 → 疑为定额分摊而非按工作量计价
- [ ] 未采用功能点法（《软件研发成本度量规范》GB/T 36964）
- [ ] 计价依据以**建筑工程定额**支撑**软件开发费** → 依据链错配
- [ ] 其他费用缺项（软件测试费、等保测评费、监理费、招标代理费）
- [ ] 正文承诺了某项措施（如等保三级测评）但估算中无预算 → **方案与估算脱节**
- [ ] 持续性支出（云资源租赁）未注明计费期间，与运营期不匹配
- [ ] 设备数量与建设点位、收费车位数未建立对应表

### 6.3 需求侧
- [ ] 建设规模按全量，收入测算仅按极小口径（**范围不对等**）
- [ ] 利用率目标值与收入测算的隐含值不一致
- [ ] 单价与周转率不匹配（6元/天 vs 4.2次/日 → 差4.2倍）
- [ ] 月租单价低于临停 → 逆向激励，但假设月租率偏低
- [ ] 缺口测算口径不明（按配建标准反算 ≠ 报告表述值）
- [ ] 未取得收费标准批复文件

### 6.4 合规侧
- [ ] **资金来源表述前后矛盾**（"自筹" vs "全部为贷款"）← **最高频立项卡点**
- [ ] 财政端三要件缺失（资金来源证明/事前绩效评估/财政承受能力评估）
- [ ] 项目性质未明确（政府投资 vs 企业投资）→ 影响审批路径与采购法律适用
- [ ] 招标标的性质与列项不符（服务类却按"设备"招标）
- [ ] "不采用招标方式"未援引法规条款
- [ ] 风险识别缺类、无四维度评价、无应急预案
- [ ] 引用了某评估的依据但无对应章节（文不对题）

## 七、报告力度与口径（🔴 关键决策点）

**用户可能同时提出两个冲突要求**：
- "别太严重，能通过评审就行"
- "要风险揭示式"

**处理原则（报数纪律）**：
1. **先向用户明示冲突**，不要自己悄悄软化。错误归因比沉默更有害。
2. 提供分级选项让其裁定，例如：
   - 全额揭示 / 分级软化 / 仅列补正清单 / 先出报告再看
3. **推荐"中性口径 + 实质保留"**：
   - 临界值 → 称"**盈亏平衡上限**"（风险提示，非缺陷指控）
   - 指标不可复现 → 称"**披露不足，建议补充测算底稿**"（不指控算错）
   - 资金来源矛盾 → 称"**表述需统一**"
   - 通篇**禁用**"错误""虚假""漏算"等定性词，改用"需补充说明""建议予以明确"

**这个组合站得住脚**：实质信息完整保留，不对编制单位作直接指控，
把判断权交给审批部门，用户在签字时无风险。

## 八、报告章节骨架（9章 → 7章精简版）

篇幅控制在 **1~2 页**是理想，但含数据复算的投资风险评估通常需 **15~20 页**。
推荐结构：

```
一、项目基本情况      （概况 / 评估依据 / 评估范围与方法）
二、投资估算复核      （算术复核 ✅ / 提请关注事项）
三、财务测算复核      （收入成本基础 / 会计计量基数 / 评价指标 / 盈亏平衡电价）
四、需求规模与收入测算复核
五、建设方案与设备配置复核
六、资金筹措与立项要件评估
              （资金来源表述 / 要件准备 / 大纲对应 / 其他事项）
七、评估结论  （主要结论 / 需补充完善事项 / 评估意见）
```

**必备的免责与方法声明**（放在第一章末尾）：
> 本次评估所依据的基础资料仅为建设单位提供的……。
> 凡本报告表述为"不可复现"或"披露不足"之处，
> 均指可研披露的数据尚不足以支撑其所列结论，
> 需编制单位补充完整测算底稿后方可作最终判断，
> **并非对测算结果本身作出定性认定**。

### 9.1 🔴 首行缩进的分类陷阱（必看，已踩坑）

**问题**：用"以冒号结尾 + 短句"判定公文**称谓**（顶格不缩进）会**误伤正文引导句**。

实例：`为便于建设单位逐项落实，本次评估汇总需补充完善的事项如下：`
（28 字、以「：」结尾）被误判为称谓 → **未设首行缩进**，被用户当场发现。

**根因**：中文公文里 `……如下：` `……包括：` `……主要有：` `……鉴于：`
这类**正文引导句极多**，与称谓形态相似，仅凭"结尾冒号 + 长度"必然误判。

**正确判据（三重条件，缺一不可）**：
```python
if (s.endswith("：") and len(s) < 30      # ① 形态
        and "，" not in s and "。" not in s  # ② 结构：无逗号/句号（引导句必有标点）
        and stats["body"] == 0):               # ③ 位置：仅限文首
    # → 判定为称谓，顶格不缩进
```

**通用原则**：用正则或条件式控制排版时，
**必须先写"否定条件"排除同类干扰项**，再定正向判据。
宁可漏判（后续人工补），不可误伤（用户一眼看出）。

**核验方法**：写**分组统计脚本**——按 主标题/一级/二级/正文/称谓/落款 六类，
分别统计"有缩进/无缩进"数量，并**列出所有无缩进的段落文本**。
比逐段人眼检查可靠得多。注意：主标题行会被误归入"正文"类，
核验时要结合位置排除。

### 9.2 报告结构体例（用户 2026-09-21 定版，实测确认）

> **本技能只定"结构"，不列版式数字。** 字号 / 行距 / 缩进 / 对齐 / 页码位置 / 标点规范

## 十一、报数纪律（用户硬要求）

**三级标注**（缺一不可）：
- ✅ **实测**：有文件时间戳/脚本输出/程序重算佐证 → 可对外
- ⚠️ **估算**：经验推断无直接证据 → **必须标"估"并请用户校准**
- ❓ **待核**：证据不完整或矛盾 → **禁用**，补测前不许出现在任何输出

**四条硬纪律**：
1. **跑批时间 ≠ 总耗时**
2. **不许把估算说成实测**
3. **记忆里的数字一律当"待核"**（含本技能中的数字）
4. **取整方向要保守**（0.1499 → 说"约0.15"，不说"0.15"；宁说"不到"不说"约为"）

**归因同样要取证**：只有现象没有机制时，**写"机制未确认"，不要给听起来合理的解释**。
- 探测失败 ≠ 事实不存在
- 命令"成功"但落到意外同名程序上 ≠ 事实
- 结论与预期不符时，**必须换独立通道复核**（推荐 Python 绝对路径）

**涉及金额一律用 `Decimal`**，不用 float。

## 十二、🔴 两种报告体例：复核式 vs 独立风险评估式（先定用哪套！）

用户可能先后提出两种要求，**体例完全不同，动手前必须确认**：

| 维度 | A. 复核式（审可研） | B. 独立风险评估式 |
|---|---|---|
| 报告对象 | **可研文本**（审它写得对不对） | **项目本身的投资风险** |
| 可研角色 | 被审核的文件 | **基础资料来源** |
| 核心句式 | "可研披露的 X 与 Y 不符" | "本项目在 X 方面存在何种风险、如何管控" |
| 骨架 | 复核项罗列（估算/财务/需求/方案/资金） | **必要性→可行性→合理性→安全性→结论** |
| 风险章 | 无独立章节 | **独立成章**（识别/评价/管控/预案） |

### 12.1 B 类体例的规范来源

### 12.4 内容替换的实现方式（保住版式的最稳做法）

**不要重建母本**。以**已定稿的 docx 为母本**，按段落类型克隆格式、只换文字：
1. 取同类段落作"格式模板"（title / salutation / body / h1 / h2 / blank / sign_unit / sign_date）
2. `copy.deepcopy(exemplar._element)` → 删除除 `w:pPr` 外全部子元素 → 追加一个新 `w:r`（其 `rPr` 亦从模板 run 深拷贝）→ 写入 `w:t`（设 `xml:space="preserve"`）
3. 删除原正文段（**保留承载分节符的那一段**），在 **body 级 `w:sectPr` 之前** `addprevious()` 逐段插入
4. Word COM 更新目录域 → 导出 PDF

→ 分节、页码重编、页脚域、`toc 1`/`toc 2`/`Hyperlink` 样式**全部自动继承，零改版风险**。
脚本模板：`<项目>/.workbuddy/tmp/rewrite_report.py`
